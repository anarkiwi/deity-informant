# Native P-Code IR

`deity_informant._native` is a Rust build of the lifter's output: every opcode's P-Code as a
compact, allocation-free template, instantiation of an instruction into a caller-owned
arena, and a reference interpreter step-for-step equal to `PcodeVM`. Wheels ship it; an
sdist install (no Rust toolchain) has the pure-Python package only and
`deity_informant.NATIVE` is false. Nothing in it knows a host: memory behaviour is the
caller's `Bus`.

## Layout

| Path | Role |
|---|---|
| `crates/di-pcode` | Pure Rust library: IR types, templates, `instantiate`/`decode_range`, `Bus`, `Cpu`. No PyO3. |
| `crates/di-pcode/src/templates_gen.rs` | Per-opcode templates, generated by `tools/gen_pcode.py`. Do not edit. |
| `crates/di-pcode/examples/bench.rs` | Decode and interpreter throughput (`cargo run --release -p di-pcode --example bench -- [sort\|random\|IMAGE] [STEPS] [PC]`). |
| `crates/di-lift` | Whole-program lifting to optimized, executable P-Code; see [wholeprog.md](wholeprog.md). |
| `crates/di-py` | PyO3 extension `deity_informant._native` (abi3): `lift`, `Cpu`, `lift_program`, `lift_many`, `reference_call`. |
| `tests/fixtures/bsort.hex` | Host-neutral bubble-sort workload shared by the bench and the trajectory test. |

Build a wheel with `maturin build --release`, or `maturin develop --release` into a
checkout's venv. `docker/native.Dockerfile` builds the wheel in a multistage image (crate
dependencies fetched in their own layer) and runs the Python suite against it.

## IR

**Varnode** (`Vn`, 32 bits): offset or constant value (bits 0-15), space (16-17:
`const`, `reg`, `unique`, `ram`), size in bytes (18-20; 0 is "no varnode"), operand slot
(21-23) and value-file index (24-31). `reg` offsets are `lift()` register-file indices
(A X Y SP = 0-3, C Z I D B V N = 8-14). `ram` is a memory cell addressed directly; the
lifter's own loads and stores go through `LOAD`/`STORE` with a computed address.

**Operand slots** bind a constant to the instruction bytes, mirroring `lift()`'s `prov`:

| Slot | Value | `prov` |
|---|---|---|
| `B1` | `b1` | `([1], "id")` |
| `Word` | `b1 \| b2 << 8` | `([1, 2], "word")` |
| `B1Inc` | `(b1 + 1) & $FF` | `([1], "hi1")` |
| `B2Inc` | `(b2 + 1) & $FF` | `([2], "hi1")` |

A template constant carries its slot and offset 0; instantiation writes the bound value
into the offset and keeps the slot, so an instance still says where each constant came
from.

**Op** (`Op`, 16 bytes): `Opc` (`COPY`, `INT_ZEXT`, `INT_ADD`, `INT_SUB`, `INT_AND`,
`INT_OR`, `INT_XOR`, `INT_LEFT`, `INT_RIGHT`, `INT_EQUAL`, `INT_NOTEQUAL`, `INT_LESS`,
`INT_LESSEQUAL`, `INT_CARRY`, `LOAD`, `STORE`; lifted programs add `BRANCH`, `CBRANCH`,
`BRANCHIND`, `CALL`, `RETURN`, `CALLOTHER`), an output and two inputs. `STORE` stores
input 1 at address input 0; unary ops leave input 1 empty. A `LOAD` with no output is an
indexed access's throw-away read of its unfixed address, made only when input 1 (if present)
is nonzero (a read's page cross).

**Template** (`Template::of(opcode)`): a slice of the shared `OPS` pool, a slice of the
shared `BINDS` pool (each operand-bound input as `op << 1 | input`), length, base cycles, penalty kind, control kind and, for `(zp),Y` penalties, the unique that holds the
loaded pointer. The stack-frame kind (`stk`) is the control kind for `jsr`/`brk`/`rts`/`rti`.

| Penalty | Rule |
|---|---|
| `Branch` | taken +1, and +1 more when target and fall-through pages differ |
| `Ax` / `Ay` | +1 when `word + X` / `word + Y` crosses a page |
| `Iy` | +1 when `pointer + Y` crosses a page |

Control kinds are `lift()`'s: `next`, `br` (flag register and polarity), `jmp`, `jmpind`,
`jsr`, `rts`, `rti`, `brk`, `jam`. `Insn::ctrl()` and `Insn::pen()` resolve targets and bases
from the operand bytes.

**Insn** (12 bytes): `pc`, opcode, `b1`, `b2` and the first op's index in the arena.
`instantiate(&mem, pc, &mut arena)` copies the template's ops into a reused `Vec<Op>` and
patches only the `BINDS` positions;
`decode_range(&mem, start, end, &mut arena, &mut insns)` sweeps a byte range linearly.

## Generation

`tools/gen_pcode.py` lifts each opcode under two sentinel sets in which the operand bytes and
the zero-page pointer they name all differ. Ops, outputs, non-constant inputs, length,
cycles and control/penalty kinds must be identical between the lifts; a constant that
differs must have a `prov` entry whose slot reproduces it in both lifts, else generation
fails. Branch and jump targets and penalty bases are checked against the operands. The
`(zp),Y` pointer unique is the single unique holding the loaded pointer after executing each
lift. `--check` (CI, and `tests/test_gen_pcode.py`) fails if the checked-in file differs.

## Interpreter

`Cpu::step(&mut bus)` fetches the opcode and its operand bytes through `Bus::fetch`, runs the
template ops with the operand slots bound, adds base cycles and the penalty, then resolves
control as `PcodeVM.step` does: stack pushes and pulls, `JMP ($xxFF)` page wrap, `BRK`'s
B-set status push and I set, the `$FFFE` vector read, and the control throw-away reads
(the byte after a one-byte opcode first, a taken branch's next byte and page-crossing unfixed
target, `RTS`'s pulled address), as `PcodeVM.step` makes them. A JAM adds its cycles and returns
`Err(Jam)` with PC unchanged. `Cpu::exec(&mut bus, &insn, &arena)` runs an instantiated
instruction; `Cpu::run(&mut bus, n)` steps up to `n`. Registers, operand slots and uniques
share one value file, so an op's operands are single indexed loads.

`Bus` has `read`, `write`, `fetch` (default `read`) and `now(cycles)` (default nothing: the
start cycle of the instruction whose accesses follow); `[u8; 0x10000]` implements it.
`Cpu::run_clocked(&mut bus, sp_above, end)` is `run_to_rts`'s loop: it stops before an
instruction once SP exceeds `sp_above` or the cycle count reaches `end`, or after a JAM, and
calls `now` before each instruction. The
only difference from `PcodeVM` is that the `Iy` penalty uses the pointer the instruction
loaded, where `PcodeVM` re-reads it from memory afterwards; they agree unless the host's
reads of those two bytes are volatile.

## Python

```python
from deity_informant import _native
rec = _native.lift(mem, pc)               # == deity_informant.lift(mem, pc)
cpu = _native.Cpu(reg=vm.reg, pc=pc, cycles=0)
cpu.step(mem)                             # mem: 65536-byte bytearray; JAM raises RuntimeError
n, jammed = cpu.run(mem, 1_000_000)
cpu.reg, cpu.pc, cpu.cycles, cpu.status()
```

`tests/test_native.py` checks `lift` equality for every opcode over random operands and
memory, single steps against `PcodeVM` (with `volatile = False`) from random states, and full
register, memory and cycle trajectories over random JAM-free images, the bubble-sort fixture
and `hello_world`.
